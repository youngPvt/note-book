# 03 Runtime 初始化与环境准备

本环节把已领取的 Run 转为可以执行的 Runtime 实例，准备可信身份、固定配置、会话映射与工作区。它处于启动阶段：环境准备成功后进入 Agent 循环，恢复任务则先核对恢复条件。

## 触发与输入输出

上游 [调度与执行所有权](../02-scheduling/README.md) 已创建 Attempt 并授予租约。输入包含 Run 配置快照、身份与策略引用、Runtime 类型和版本、输入材料，以及可选恢复清单。输出是绑定当前 Attempt 的执行上下文、Runtime 句柄、会话映射和环境引用，交给 [意图理解与规划](../04-intent-planning/README.md)。初始化失败返回明确原因，不进入模型循环。

## 初始化步骤

1. **读取可信快照。** 服务端按 `run_id` 获取已固定的 AgentVersion、Prompt、Skill 版本与预算，核对租户、工作区和调用身份。模型文本不能覆盖这些身份字段；重试不重新选择最新版本。
2. **核对 Runtime 能力。** 适配器声明工具注入、流式事件、取消、在线确认、持久化等待和跨进程恢复等能力。任务要求与能力不匹配时拒绝启动，不能把 SDK 的同名接口视为相同恢复语义。
3. **准备受限环境。** 创建 Attempt 独立工作区，恢复仓库基线、输入文件和必要依赖；固定镜像、可写目录、网络与资源限制。恢复任务还要对齐 checkpoint、文件快照和未决操作。
4. **受控绑定模型与工具。** 解析模型路由和工具端点，通过凭证代理或受限通道准备访问。模型密钥不进入 Prompt、日志或任意脚本可读的环境；工具权限在实际调用时再次检查。
5. **建立会话映射。** 保存平台 `session_id/run_id/attempt_id` 与执行器 session/thread、工作区、恢复引用的映射。同一平台 Session 的写入按调度规则串行，运行句柄只代表当前进程内实例。
6. **完成就绪提交。** 检查模型路由、工具连接与环境可用性，记录配置摘要和就绪事件。失败时按已创建资源逆序清理，保留诊断信息并撤销临时凭证。

## 边界与故障

例如续跑一个已修改代码的任务，只有聊天记录而没有相应补丁，不能让新 Worker 从旧仓库直接继续。先走 [等待与恢复](../13-wait-recovery/README.md) 核对材料，无法恢复时保留原因。

初始化不负责为每项任务预先装载所有资料，也不执行 Skill 脚本。已选 Skill 的正文与后续资源由循环按需装载；脚本仍通过执行门禁与工具执行路径。

DeepSeek Harness 将模型适配、工具、会话日志和 Agent Loop 都作为可组合插件。这可用于理解 Runtime 内部能力拆分；平台的租约、租户授权和环境准备仍需明确实现。[固定版本架构说明](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/docs/architecture.md)
