# 组件协作与故障处理

Agent 根据组件返回的结果选择下一步，Runtime 落实等待、恢复与停止，工具及业务服务执行实际动作的校验。Skill 提供方法指导，各组件保留自身的授权、版本和持久化职责。以下场景连接工具、Skill、知识、沙箱、产物和观测模块。

## 跨模块故障

| 故障 | 处理方式 |
| --- | --- |
| 工具调用响应丢失 | 查询稳定操作 ID 对应结果，再决定重试或转人工核对 |
| Skill 发布后引入错误 | 停用问题版本，发布回滚配置，评估进行中的 Run |
| 沙箱退出但文件尚未归档 | 标记产物不完整，从已有持久化边界恢复或明确失败 |
| 向量索引滞后 | 返回前检查主记录与权限，按能力降级查询并标明版本 |
| 观测服务不可用 | 缓冲与重试遥测，核心运行状态和必要审计继续持久化 |
| 用户权限被撤销 | 阻止后续访问，停止受影响调用，清理或重建已包含受限内容的上下文 |
| Skill 步骤被跳过，直接请求交付 | 业务服务检查当前 Commit 或产物版本的必需验证与审批，缺少证据时拒绝执行 |
| 修改后继续引用旧测试报告 | 按代码或产物版本核对证据，旧版本通过不作为当前版本的交付依据 |

详细设计见 [工具调用](../../06-mcp/README.md)、[Skill 管理](../../07-skills/README.md)、[知识检索](../../08-knowledge/README.md)、[沙箱与工作区](../../09-sandbox/README.md)、[产物](../../10-artifacts/README.md)、[可观测性](../../11-observability/README.md) 和 [上下文管理](../../03-context/README.md)。

## 面试表达

> 公共组件把执行过程需要的能力做成统一服务。MCP 和 API 适配器负责连接企业工具，Skill 提供可复用方法，沙箱承载命令和代码执行，产物服务保存可检查的结果。我们用统一的身份、版本和执行标识把这些组件连起来，再通过观测与评测验证执行是否稳定、结果是否有用。
