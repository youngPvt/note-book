# 12 完成交付

本环节对完成候选进行独立于模型自述的验收，持久化结果与证据，再提交 Run 终态并交付调用方。

## 触发与输入输出

[循环控制](../11-loop-control/README.md)核对未决动作、子任务与停止条件后，将完成候选交入本环节；循环或恢复处理决定失败、取消、超时后，也通过本环节保存结束原因并收尾。输入包含固定的输出要求、最终答复、动作结果、产物清单和验证证据。输出为已交付结果、需要继续修正的反馈，或明确的失败与等待原因。

未通过且仍可修复时返回循环，通过后保存结果并发送终态事件。普通问答可以直接交付文本，不强制生成文件，也不要求用另一个模型充当裁判。

## 基本步骤

1. **核对结束条件。** 检查任务目标、必需输出和未决动作，区分已完成、仅生成草稿、等待外部确认及预算耗尽。不能把 SDK 的正常结束或模型最终消息直接映射为业务成功。
2. **验收交付对象。** 根据契约检查结构、内容和外部验证结果。研发任务绑定仓库、Commit 或产物摘要，测试与审查证据须对应这次交付版本。后续修改代码后，旧报告不能继续证明新版本合格。
3. **确认交付权限。** 检查收件主体、资源归属、当前下载权限和敏感内容范围。向外部系统发布、发信或提交变更属于另一个受控动作，仍需经过动作前检查与工具执行，不因进入交付环节自动获准。
4. **先保存结果。** 持久化最终文本、必要产物、校验结论与引用清单，确认对象可读取且摘要匹配。必要产物保存失败时暂不提交成功，依据可恢复条件重试或保留失败原因。
5. **提交终态与事件。** 以当前 Attempt、所有权令牌和状态版本作条件更新，事务性保存终态与待通知事件。完成与取消竞争时按被接受的状态转换处理，迟到回调不能覆盖终态。通知可重发，消费者按事件 ID 去重。业务回写、用量结算及长期记忆候选提炼可消费结果事件，记忆发布仍须验证，不能直接把模型总结写成已确认事实或覆盖已发布 Skill。
6. **清理运行资源。** 归档恢复与审计材料后，关闭无需保留的会话、子进程和临时工作区，回收临时凭证，结算租户用量并释放并发额度。清理失败记录补偿任务，实际仍占用的资源不能虚报已释放。

## 边界与失败

Run 成功表达本次调用达到约定要求，上层需求、工单和发布状态仍由业务系统维护。外部通知失败不应让已经成功的任务重新执行，订阅者重连后可查询已保存结果。

独立验收强调检查真实对象和证据，可采用确定性规则、测试工具或人工确认。模型评估可以补充语义判断，但不能替代资源权限、版本匹配和必需测试。

Codex app-server 的 `turn/completed` 携带该 Turn 的最终状态，宿主应用仍需解释结果并执行自身验收。[Codex 生命周期](https://learn.chatgpt.com/docs/app-server#lifecycle-overview)
