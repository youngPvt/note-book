# 07 模型调用

本环节将已组装的上下文提交给允许使用的模型，并把完整响应转换为可校验的动作提议或完成候选。

## 触发与输入输出

[上下文组装](../06-context-assembly/README.md)完成后，当前 Run 仍允许运行且需要模型决策时进入本环节。输入包含配置快照、消息与工具定义、输出要求、剩余预算和可信执行上下文。输出是带调用标识的消息、完整工具调用、完成候选或明确错误。

工具提议交给[动作前检查](../08-pre-action-gate/README.md)，完成候选与调用错误交给[循环控制](../11-loop-control/README.md)。循环控制核对未决动作、子任务与停止条件后，再提交[完成交付](../12-completion-delivery/README.md)。模型返回成功不代表任务已经验收通过。

## 基本步骤

1. **检查调用条件。** 核对 Run、Attempt 所有权、取消标记、截止时间与剩余预算，确认快照指定的模型策略仍被当前租户和 Agent 允许。停用或撤权后停止新调用。
2. **确定请求参数。** 根据固定策略选择模型、输出格式、采样参数和输出上限。检查输入容量并预留输出空间，超限先返回上下文环节压缩或裁剪。只允许使用快照已声明的备用模型，记录实际选择。
3. **预留与发起。** 申请并发额度并预留本次费用或 token 预算，生成模型调用 ID，记录模型、参数、上下文摘要、工具集合及来源版本。凭证通过受控引用获取，日志不保存密钥。
4. **接收与组装流。** 区分消息增量、工具调用参数增量、用量及结束事件。按调用 ID 组装，只有协议确认完整的工具调用才能进入动作前检查，不能执行半段 JSON。连接关闭也不能代替成功结束事件。
5. **解释与结算。** 检查结束原因、拒绝、截断和输出结构，保留各工具调用与参数。回收预留额度并登记实际用量，缺失用量单独标记待核对，不按零成本处理。

## 边界与失败

超时、限流和临时网络故障按统一预算有限重试，不能与 SDK 自带重试叠加成无界调用。模型请求重试通常留在当前 Attempt，重新分配 Worker 才创建新 Attempt。已处理的动作提议需要去重，连接重试不能导致工具再次写入。

输出被截断、结构不合法时可以有限修复或重问。无法确认模型服务是否完成的请求保留调用记录，核对用量后再决定后续动作。普通问答可以直接得到完成候选，不要求先调用 Skill 或工具。

自有循环可以落实每次请求前检查。Codex 的 `PreModelRequest` 和 `PostModelRequest` 仅提供诊断，不能修改上下文或拦截请求，因此接入时应根据实际 SDK、运行参数和外围控制声明可执行的限制。[Codex hooks](https://learn.chatgpt.com/docs/hooks#premodelrequest-and-postmodelrequest)
