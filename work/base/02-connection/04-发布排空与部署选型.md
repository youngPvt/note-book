# 发布排空与部署选型

部署设计要减少发布引起的连接中断，并确保中断后能够恢复业务状态。以下是实现与验收建议，选型按现有技术栈、连接规模和恢复要求决定。

## 部署职责与拆分时机

| 单元 | 保留的职责 |
| --- | --- |
| WS 网关 | 连接、认证接入、订阅、心跳、限流与消息转发 |
| 业务会话服务 | 消息、会话归属、访问校验、命令分类及 Run 关联 |
| 执行服务与 Worker | Run 幂等创建与调度、Attempt、Agent 循环、工具与产物 |

网关保持精简，任务状态不只放在连接对象里。小规模可以把网关与业务会话服务合并部署，保持逻辑边界，Worker 独立运行。仅拆代码模块不能避免发布断线，独立部署和独立发布后，业务服务更新才不会同时终止承载连接的进程。网关自身发布和网络失败仍需要重连。

## 有限时间的发布排空

1. 新实例先就绪，旧实例进入 draining，停止接收新连接，保留存量连接的必要服务。
2. 更新 readiness，并考虑 Service、Ingress 和外部负载均衡配置传播的时间差。应用侧也拒绝新的握手，避免传播期间继续接入。
3. 在限定期限内完成当前短消息处理，分批提示客户端重连并加入随机抖动，防止大量客户端同时冲击新实例。
4. 截止后关闭剩余连接、释放连接资源。已接收的业务命令由持久化记录继续处理，不能因连接关闭重新执行或取消 Run。

Kubernetes 终止过程会更新端点状态，`preStop` 先于容器停止信号，且消耗同一份宽限时间。应给传播等待、应用排空和最终退出留足总预算，超时仍可能被强制终止。readiness 与排空不会把已有 TCP 连接迁到新 Pod。[Pod 终止机制](https://kubernetes.io/docs/concepts/workloads/pods/pod-termination/#pod-termination-flow)

## 传输与托管选项

以服务端输出为主时，可采用 HTTP 提交命令、查询状态与 SSE 推送。浏览器原生 `EventSource` 按规范处理重连及非空 `Last-Event-ID`，服务端仍负责保存与补发。使用 `fetch` 自行消费流时，要自己实现相应解析、游标和重连逻辑。[EventSource 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-last-event-id-header)

Socket.IO 可减少心跳、重连等接入工作，但连接恢复有窗口和失败分支。普通 Redis adapter 使用 Pub/Sub，不支持连接状态恢复，Redis Streams adapter 支持外部保存会话与流数据，仍需检查保留范围及异常恢复条件。[Redis adapter](https://socket.io/docs/v4/redis-adapter/) · [Redis Streams adapter](https://socket.io/docs/v4/redis-streams-adapter/)

保留 HTTP long-polling 时通常需要粘性会话。仅使用 WebSocket 传输时，一条长连接已固定到实例，无需这一类粘性配置，但跨节点投递和重连状态共享仍需处理。[多节点部署](https://socket.io/docs/v4/using-multiple-nodes/#disabling-http-long-polling)

AWS API Gateway 可托管客户端 WebSocket 并按消息路由到后端，这有助于分离连接与业务部署，不代表任务状态自动恢复或连接永不关闭。[AWS WebSocket API](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-websocket-api-overview.html)

Azure SignalR Service 的 Default 模式支持配置 `MigrateClients`，在有有效目标服务、当前消息完成且未超过排空期限等条件下尝试迁移。失败仍可能断开，应用会话状态也须自行处理，不能推广为普通 WS 都能迁移。[SignalR 优雅关闭](https://learn.microsoft.com/en-us/azure/azure-signalr/server-graceful-shutdown)

## 验收场景与面试追问

建议验证滚动发布、网关强制退出、上游通知中断、客户端集中重连和慢连接排空超时。观察新连接接入、重连峰值、Run 是否继续及状态能否收敛，保留实际结果，不预设发布零断线。

1. 为什么网关与业务代码分目录后，发布仍会断线？
2. `preStop` 等待时间过长会怎样影响应用退出？
3. SSE 或托管网关分别省掉哪些工作，还要自行保存什么？
