# 连接接入的官方实践与设计边界

连接恢复、业务状态同步和后台任务执行分别解决不同问题。WebSocket 协议规定连接行为，云服务与框架提供部分连接治理能力，平台仍需建立 Session、Run、权限和持久化契约。下列资料核对于 2026 年 11 月 16 日，不据此推定历史项目已经完成这些能力。

## 官方能力与适用边界

| 资料 | 可采用的机制 | 需要保留的边界 |
| --- | --- | --- |
| [RFC 6455 7.2.3](https://datatracker.ietf.org/doc/html/rfc6455#section-7.2.3) | 异常关闭后随机延迟、递增退避重连 | 协议不负责恢复 Session、Run 或离线业务事件 |
| [AWS API Gateway 连接模型](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-basic-concept.html) | 客户端连接由网关持有，收到消息后调用后端集成 | 这是一种连接与应用分离实现，不要求每个自建平台使用 AWS |
| [微软 Web API 长任务指南](https://learn.microsoft.com/en-us/azure/architecture/best-practices/api-implementation#provide-asynchronous-support-for-long-running-requests) | 可靠记录任务、异步 Worker、状态查询、实时通知 | 进程内未跟踪的后台任务不能抵御接入服务重启；通知不能替代状态查询 |
| [Socket.IO 投递保证](https://socket.io/docs/v4/delivery-guarantees/) | 应用可通过事件 ID、持久化及接收游标补发遗漏事件 | 默认投递是 at-most-once，重连本身不保证服务端事件补发 |
| [Socket.IO 连接恢复](https://socket.io/docs/v4/connection-state-recovery/) | 可选的有限窗口恢复机制 | 恢复可能失败，仍需重新同步；权限变化不能因恢复而跳过 |
| [Redis adapter](https://socket.io/docs/v4/redis-adapter/) 与 [Redis Streams adapter](https://socket.io/docs/v4/redis-streams-adapter/) | 前者跨节点转发，后者支持连接状态恢复 | Pub/Sub 本身不持久化回放；使用 Streams 仍要定义保留时间及故障范围 |
| [Kubernetes Pod 终止](https://kubernetes.io/docs/concepts/workloads/pods/pod-termination/) | 终止状态、就绪状态与宽限时间支持排空 | 已建立的 WS 不会自动迁移；超时后进程会被终止 |
| [Azure SignalR 优雅停机](https://learn.microsoft.com/en-us/azure/azure-signalr/server-graceful-shutdown) | Default 模式下可尝试迁移客户端的后端路由 | 需可用目标、处理完当前消息并在时限内完成；失败仍会断连 |
| [HTML EventSource 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html) | SSE 的原生 EventSource 重连与 Last-Event-ID | 历史查询、权限及补发由服务端实现；手写 fetch 流读取不自动获得整套机制 |

## 本平台的取舍

保留已有 WS 通道，连接网关只承载连接和消息接入。会话管理保存用户交互，执行层维护 Run 的权威状态和执行资格，Worker 独立运行。先做状态同步，确有完整过程回放要求时再增加事件游标。

小规模时连接与会话可以合并部署；当业务发布需要避开长连接，或连接量需要单独扩缩容时再拆分。独立连接服务降低应用发布的影响，但其自身故障仍需要客户端重连。托管连接服务可以减少维护工作，不能取代运行状态、授权检查和副作用幂等。

## 验收时要观察的结果

以下是设计验收场景，不是已完成的线上故障复盘。

| 场景 | 应观察到的结果 |
| --- | --- |
| 任务接收后重启网关 | 客户端换节点恢复，原 Run 不变；Worker 未失效时 Attempt 不变 |
| 接收确认返回前断连 | 原幂等键重试找到同一 Run；同键不同输入返回冲突 |
| 同一会话在两个页面提交新任务 | 按会话规则排队，执行层仅允许一个独立主 Run 持有执行资格 |
| 原 Run 等待用户回答 | 回复通过控制通道进入原 Run，不堵在其后的新任务队列里 |
| 状态同步期间又产生更新 | 快照版本与后续更新正确衔接，缓冲溢出能够重新同步 |
| 历史事件已过保留期 | 明确退回快照同步，不宣称遗漏事件已全部补齐 |
| 重连时用户权限已撤销 | 订阅或控制被拒绝，不能依赖旧连接曾通过认证 |
| 客户端持续读取过慢 | 缓冲有界，触发降速、合并可覆盖状态或重新同步，不拖垮 Worker |
