# 06 工具执行与副作用记录

本环节执行已经通过门禁的具体调用，管理派发、并发、超时与结果记录。模型负责提出动作，工具服务实际执行；调用成功与业务任务完成分别判断。

## 触发与输入输出

上游 [执行前门禁](../05-pre-action-gate/README.md) 提交已校验参数、身份、授权决定和操作标识。执行器派发前仍检查取消、租约与决定有效性。输出包含调用状态、结果或产物引用、错误类别及副作用记录，交给 [执行后校验](../07-post-action-check/README.md)。后台任务只返回已受理状态与 job 引用，不能当作最终成功。

## 执行步骤

1. **记录调用意图。** 对写操作先保存稳定 `operation_id`、目标、规范化参数摘要和执行状态。操作 ID 代表一次业务动作，跨 Attempt 重试沿用；模型重复提议不能直接当作新的合法写入。
2. **选择执行通道。** SDK 原生工具、MCP 企业工具、沙箱中的 Skill 脚本均绑定当前身份、操作标识与取消信号。动作需要文件、代码或脚本环境时，再按授权策略申请或复用当前 Attempt 的工作区与沙箱，保存环境引用并确认就绪后执行。环境创建采用稳定标识，结果未知先查询，不能重试就新建一份。纯远端 API 调用不必建立本地沙箱。原生 Shell 仍受文件、网络和凭证策略约束，不能依靠 MCP 门禁保护另一条直连路径。
3. **控制并发。** 独立查询可受限并行；写同一文件、同一资源或存在先后依赖的动作串行。只依据工具名标记“可并行”不够，还要判断资源冲突，并为结果保留各自 call ID。
4. **派发并追踪。** 记录开始时间、次数和截止时间。幂等键交给支持它的下游，结合业务唯一约束与状态查询。启动长任务时先保存 job 映射，后续查询、取消和结果回收继续绑定原操作。
5. **归一化结果。** 分开记录未派发、已完成、明确失败与结果未知，保存必要错误码和产物引用。大结果可落文件并返回有范围的摘要，关键字段不能静默截断。

## 超时与重复执行

“创建工单”已发送但响应超时，可能已经创建成功。此时标记结果未知，按操作 ID 或业务标识查询下游；确认未执行且仍获授权才重试，持续未知进入 [等待与恢复](../10-wait-recovery/README.md)。取消本地等待也不能证明远端停止。没有下游幂等或可靠对账时，平台不能声称外部写入恰好一次。

Worker 接管后，同一业务动作继续使用原 `operation_id`，新 Attempt 的 owner epoch 只标识当前执行权。受控服务校验 epoch 可以拒绝旧实例的新写入，但不能撤销已经发出的请求。外部 API 必须真正支持约定作用域与有效期内的幂等键，或提供可靠的结果查询；仅在本地记录操作 ID 不会自动防重。恢复先核对未知结果和后台 job，再按剩余预算决定重试，不能无限重试或宣称外部写入恰好一次。详见 [恢复清单与跨 Worker 接续](../10-wait-recovery/02-恢复清单与跨Worker接续.md)。

DeepSeek Harness 的共享调用管道包含 `tools/pre-execute`、不可被后续许可放宽的拒绝守卫、`tools/execute`、`tools/post-execute`，最终通过 `tools/result` 观察冻结结果；审批不可用时需要确认的调用被拒绝。这体现了通道内统一治理，具体业务授权与幂等仍需自行接入。[固定版本工具管道](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/docs/tool-execution-pipeline.md)
