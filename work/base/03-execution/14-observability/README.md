# 14 事件记录与全程观测

本环节贯穿任务、模型、工具、等待、恢复和交付，产生持久状态、必要事件与观测数据，记录任务发生了什么、用了多少资源、为什么失败。[连接模块](../../02-connection/README.md) 负责 Session 历史访问、客户端订阅、状态同步与推送；执行层在事件发生时记录事实，不等任务结束后补日志。

## 触发与交接

| 项目 | 约定 |
| --- | --- |
| 触发 | Run 状态变化、模型请求、Skill 加载、工具调用、审批、恢复及产物提交 |
| 输入 | 可信执行标识、实际事件、耗时、用量、版本和错误信息 |
| 输出 | 权威运行状态、带水位的快照来源、必要运行事件、审计证据、Trace 与指标 |
| 使用者 | 连接层的状态同步与推送、排障、用量结算和离线评测 |

## 基本处理步骤

1. 用 Session、Run、Attempt、Trace 和操作 ID 关联记录，模型与工具事件保留其调用标识。框架的 Thread、Turn、Item 等对象通过适配器映射，不直接当作同名业务对象。
2. 在发生时记录配置摘要、当前策略修订号、模型调用、Skill 搜索与加载、上下文裁剪、工具门禁与结果，明确开始、结束、失败或结果未知。
3. 核心状态、必要操作与审计可靠持久化，通知通过 outbox 等方式异步发布。中断请求已接收与执行已经停止使用不同事实表达；进度流断开不改变后台任务状态。
4. 向连接层提供一致的快照与版本契约：基础模式用同一对象、同一投影的 `state_version` 衔接更新，缺口或不确定时重新查询状态。需要持久事件回放时，再明确快照已覆盖的事件水位，供补取其后记录。连接层负责鉴权、订阅、重连补取、去重与推送；具体约定见 [断线重连与状态恢复](../../02-connection/03-断线重连与状态恢复.md)。
5. 分别汇总排队、环境启动、召回、模型、工具和人工等待耗时；记录实际或估算 Token、重试费用和有效交付成本。
6. 最终用输入、动作、外部结果和产物证据进行评测，定位故障发生在哪个环节，不依赖读取模型隐藏推理。

## 边界与失败处理

运行状态、审计和遥测有不同可靠性要求：Trace 可以采样，Run 终态、必要操作记录和审批依据不能因采样而丢失。必要证据无法保存时，相关受控动作应暂停或失败；普通遥测短暂故障可缓冲、重试并记录缺口。

token delta 等瞬时展示内容可合并或仅通过实时通道传递，不要求每个 token 持久化。模型完整输出或检查点按 Runtime 恢复契约保存，必要业务状态与结果仍须落盘。全量回放只能承诺实际保存并仍在留存期内的记录，不能把实时流到达当作持久化完成。快照版本、token 序号与消息总线位置不能直接混比；采用事件回放时，快照水位必须与已包含的事件一致，不能随意填入最新序号。过期游标由连接层回退到快照。

SDK 未暴露内部模型调用、完整用量或上下文变化时，记录未知与可见边界，不能用零值代替。Runtime 是否结束以适配器确认的生命周期为依据，平台 Run 终态以 [完成交付](../12-completion-delivery/README.md) 环节的持久化状态为准，不能用某一条文字消息或工具完成事件代替整次任务结束。

日志和事件默认保留必要标识、摘要与引用。敏感正文、工具返回和产物按授权及留存规则处理，凭证正文不进入日志；查看运行记录也要校验租户与主体权限。回放记录用于复盘，不能跳过当前授权重发历史写操作。

本环节把运行状态与事件提供给连接层，把遥测交给观测系统。连接路由和 WebSocket 生命周期不归执行器管理；指标存储、采样与告警设施归 [可观测性模块](../../12-observability/README.md)，评测样本、判定器与质量指标归 [评测模块](../../13-evaluation/README.md)。

## 面试追问

1. 用户只说任务慢，如何区分排队、模型、工具和人工等待？
2. 状态快照的水位代表什么，为什么不能直接取最新事件序号？
3. SDK 没暴露内部 Token，用量应该记录什么？
4. 为什么任务结束事件、业务验收和模型最终文本要分开？
