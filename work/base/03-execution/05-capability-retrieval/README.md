# 05 能力发现与资料检索

本步骤回答当前任务可以使用什么方法、工具和证据，输出候选能力及必要内容。它贯穿 Agent 循环，首次准备和工具反馈出现信息缺口时都可触发。以下为平台设计，候选发现不会授予新权限。

## 输入、输出与协作

输入来自 [任务理解](../04-intent-planning/README.md) 或 [循环控制](../11-loop-control/README.md)，包含当前问题、子任务、已有证据、可信身份、固定版本和预算。结果交给 [上下文组装](../06-context-assembly/README.md)，并保留未命中原因与来源。

| 资源 | 先取得什么 | 进一步读取什么 |
| --- | --- | --- |
| Skill | 名称、用途、适用条件与版本 | 正文及当前需要的参考、脚本、模板 |
| 工具 | 名称、说明和接口契约 | 被选工具的参数定义与调用要求 |
| 知识 | 授权片段、来源及文档版本 | 相邻段落、章节或原文 |
| 长期记忆 | 相关条目、作用域和验证状态 | 必要事实、经验及支持证据 |
| 产物 | 清单、摘要、大小和稳定引用 | 指定文件或范围内容 |

## 基本步骤

1. 用当前目标与反馈构造查询，避免始终重复最初一句话。入口明确指定的少量方法可以直接校验加载。
2. 从可信身份计算可用范围，与 AgentVersion 启用集合及版本约束取交集，再在该范围内召回。失效或撤权资源不进入可用结果。
3. 比较用途、输入对象和适用条件，选择少量候选。允许没有匹配结果，也允许任务无需 Skill 直接调用已有工具。
4. 按需展开内容，记录资源 ID、版本、读取范围和来源。缓存命中仍检查当前访问资格，包已下载不能证明正文仍在模型上下文中。
5. 把结果送回循环，根据新证据决定是否补搜、扩大读取或请求澄清，并限制重复查询次数和累计成本。

“订单列表增加创建人筛选”可以先找仓库修改方法与订单接口资料，读到权限过滤实现后再查询相应规则，无需一次加载全部目录。

模型发起的搜索、加载和检索也是工具调用，经过 [动作前检查](../08-pre-action-gate/README.md)、[工具执行](../09-tool-execution/README.md) 与 [结果检查](../10-post-action-check/README.md)。平台直接预加载的读取也执行等价访问和结果检查。

## 故障与边界

零命中要区分没有资源、解析失败、范围过滤和候选遗漏。描述相似时用适用条件消歧，目录超预算时保留可调用的发现入口。检索超时、无权限和真实无结果分别返回，避免错误驱动无限补搜。

模型需要工具定义或受控调用入口才能执行工具，读取工具说明本身不完成接入。附属资源缺失是否阻断任务，取决于当前动作是否需要它。

Pi 会先公布 Skill 名称、描述和路径，按任务读取正文，显式 `/skill:name` 可强制展开。该机制仍可能漏选，不能当作召回正确性的保证。[Pi Skill 文档，固定源码版本](https://github.com/earendil-works/pi/blob/04fd0897e4df737cd8422bc99085d6953da804ec/packages/coding-agent/docs/skills.md)
