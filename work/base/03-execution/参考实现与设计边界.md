## Codex 可以参考什么

Codex Harness 提供会话状态、工具交互、执行事件、沙箱与审批等能力，宿主应用保留业务规则和工具的职责。可据此把企业入口、Run 状态和业务验收放在平台侧，通过适配器接入运行循环。[Harness 定位](https://developers.openai.com/blog/codex-as-a-platform)

app-server 区分 Thread、Turn 和 Item，支持事件流、会话恢复与中断。平台的 Session、Run 和 Attempt 需要定义映射，不能直接一一套用；收到请求或中断确认，也不等于业务执行已经成功或所有外部动作已经停止。[app-server](https://learn.chatgpt.com/docs/app-server)

当前 hooks 的能力存在具体限制：模型请求前后 hooks 主要用于诊断；工具 hooks 仅覆盖支持路径，后置 hook 无法撤销副作用。平台不能把 hook 名称当作完整的权限控制承诺，应按覆盖范围设计检查位置。[Hooks](https://learn.chatgpt.com/docs/hooks)

沙箱限制实际文件与网络访问，审批管理动作确认；两者共同作用。SDK 提供程序化接入，app-server 提供更直接的协议控制，某个 SDK 版本未封装的能力不能视为已经可用。[审批与沙箱](https://learn.chatgpt.com/docs/agent-approvals-security)、[Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)

## Pi 可以参考什么

Pi 的 `pi-agent-core` 承担循环和工具执行，`pi-coding-agent` 在其上组织会话、编程资源与扩展。核心请求准备包含上下文变换和模型消息转换两个位置，可帮助区分“选择材料”与“适配供应商协议”。[Agent 循环源码](https://github.com/earendil-works/pi/blob/04fd0897e4df737cd8422bc99085d6953da804ec/packages/agent/src/agent-loop.ts)

当前扩展的 `tool_call` 位于参数初次校验之后，可阻止或修改调用，修改后的参数不会自动重验。企业接入需要针对最终参数再次检查。`context` 与 `context_with_system` 的输入范围也不同，扩展点的实际时序和数据范围必须核对当前版本。[扩展接口](https://github.com/earendil-works/pi/blob/04fd0897e4df737cd8422bc99085d6953da804ec/packages/coding-agent/docs/extensions.md)

Skill 采用元数据发现、按需读取正文或显式调用的方式；这提供方法内容，不保证模型必然读取或执行全部步骤。压缩生成摘要与保留片段，原始会话记录仍有独立用途。[Skills](https://github.com/earendil-works/pi/blob/04fd0897e4df737cd8422bc99085d6953da804ec/packages/coding-agent/docs/skills.md)、[Compaction](https://github.com/earendil-works/pi/blob/04fd0897e4df737cd8422bc99085d6953da804ec/packages/coding-agent/docs/compaction.md)

会话日志通过条目关系组织历史；回到一个会话分支并不回滚文件或外部写入。Pi 默认继承进程权限，插件也在进程内运行，企业隔离要由实际执行环境和受控工具补齐。这里讨论 core 与 coding-agent，不把其他包的能力自动计入。[会话格式](https://github.com/earendil-works/pi/blob/04fd0897e4df737cd8422bc99085d6953da804ec/packages/coding-agent/docs/session-format.md)、[项目与权限说明](https://github.com/earendil-works/pi/blob/04fd0897e4df737cd8422bc99085d6953da804ec/README.md)

## DeepSeek Harness 可以参考什么

DeepSeek Harness 通过 Cordis 插件组合模型、工具、会话日志与 Agent Loop。会话日志投影模型上下文，持久化事实与进程内事件分开，适合参考服务与事件的职责划分。[架构说明](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/docs/architecture.md)

默认循环中的 step 组织模型请求及其工具调用，turn 可以包含多个 step。请求前有输入处理与适配准备位置；已有 hook 的可修改字段有限，不能据此推断任意时点都能替换模型配置。[循环实现](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/agent-loop/src/agent.ts)

工具管道区分执行前处理、拒绝守卫、实际执行、执行后处理与结果通知。确认能力缺失时可以拒绝要求确认的动作，但平台业务授权、幂等与验收仍需自行落实。[工具执行管道](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/docs/tool-execution-pipeline.md)

持久化能力依赖后端；没有 persistence 时仅保存内存状态。默认循环没有内置 turn 总预算，外部调用缺少结果时可标记 `TOOL_OUTCOME_UNKNOWN`，补齐记录不自动重试未知动作。平台需要另行实现预算和副作用核对。[循环能力及限制](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/agent-loop/README.md)

压缩记录摘要及替换范围，注意保留工具调用与结果配对；它是上下文管理能力，不能替代任务状态与产物持久化。仓库安全说明把项目标为开发预览，采用前仍需按实际环境验证隔离与权限边界。[压缩设计](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/docs/subsystems/compaction.md)、[安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/SAFETY.md)

## 接入平台时必须明确的边界

| 能力 | 可参考的机制 | 本平台仍需明确或实现 |
| --- | --- | --- |
| 任务接入与调度 | 会话、请求和循环入口 | 可信租户、Run 快照、幂等接入、队列、配额、租约和 Attempt |
| 意图与计划 | 模型根据目标和反馈选动作 | 是否需要独立路由、澄清条件、计划状态及重规划预算 |
| 召回与上下文 | Skill 发现、消息变换、压缩 | 租户范围过滤、索引质量、内容预算、证据来源与撤权处理 |
| 动作门禁 | hook、审批接口、工具拦截位置 | 全路径权限覆盖、最终参数校验、业务条件与实时限制 |
| 工具执行与结果 | 原生工具、插件管道、工具结果事件 | 稳定操作 ID、外部结果核对、并发冲突和不可信内容处理 |
| 等待与恢复 | 会话持久化、取消、继续执行 | SDK 会话与配置、工作区、产物、未决操作的一致性 |
| 完成交付 | 运行结束事件或最终响应 | 真实验收、必要产物持久化、终态提交、通知和资源回收 |
| 可观测性 | 模型、工具和会话事件 | 统一关联标识、可见性缺口、业务审计、成本与效果口径 |

本次核对的是文档与源码边界，没有把三套 Runtime 部署运行或作性能对比。选用某个适配器时，还需验证具体版本的调用、恢复与门禁覆盖；本目录中的接口和状态设计属于平台方案。
