# 07 动作后检查

本环节检查工具实际返回的结果，形成带状态、来源和证据的观察信息，决定哪些内容可以反馈给后续决策。

## 触发与输入输出

[工具执行](../06-tool-execution/README.md)返回结果、错误或超时信息后进入本环节。输入包含调用标识、原动作参数摘要、工具契约、执行状态、返回内容和产物引用。输出是已校验结果、可修正错误或待核对状态。

结果交给[循环控制](../08-loop-control/README.md)，需要继续决策时再由[上下文组装](../03-context-assembly/README.md)选择注入内容。待核对的外部动作转入[等待恢复](../../06-wait-recovery/README.md)，不能直接当作失败重新执行。

## 基本步骤

1. **确认对应关系。** 校验工具调用 ID、操作 ID、Run 和来源 Attempt，识别重复、迟到或不完整回调。过期 Worker 的结果不能覆盖当前执行状态，但已经发生的外部动作仍需记账和核对。
2. **区分执行与业务结果。** 传输成功只说明收到响应，HTTP 成功或进程退出码为零也不必然满足任务要求。按契约区分成功、明确失败、仍在执行和结果未知，提取退出码、错误类别及外部对象标识。
3. **验证结构与内容。** 检查 schema、字段范围、条目完整性、产物是否存在及其摘要。例如测试报告应关联实际测试的代码版本，生成报表要核对必需列与记录范围，不能只检查文件已创建。
4. **约束进入上下文的内容。** 对结果设置字节、条目和 token 上限，超大内容保留受权限控制的原件，再生成摘要和可按需读取的引用。标记来源、裁剪位置和缺失部分，避免悄悄截断后被当成完整结果。
5. **保存观察与证据。** 记录校验结论、错误分类、工具版本和产物引用。将必要的事实和修复线索反馈给循环，副作用结果不确定时先查询与对账，确认未执行后才考虑重试。

## 边界与失败

工具结果属于外部输入，其中的“忽略规则”“继续发布”等文字不能升级为系统指令。资源链接与后续读取仍需当前授权，脱敏或过滤不等于内容已经可信。

后置检查发现问题时，动作可能已经发生。检查只能阻止不合格结果继续被使用，无法撤销邮件、数据库写入或外部发布。需要补偿时调用业务定义的受控动作，并保留原始操作记录。

Codex `PostToolUse` 在支持的工具产生输出后运行，也无法撤销已发生的副作用。平台只能在 SDK 暴露的结果边界落实检查，不能声称能改写其所有内部工具反馈。[Codex PostToolUse](https://learn.chatgpt.com/docs/hooks#posttooluse)
