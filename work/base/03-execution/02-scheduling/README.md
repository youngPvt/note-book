# 02 执行准入与归属管理

本环节检查目标实例是否能立即接收任务，并维护 Session 执行资格、实例槽位和 Attempt 所有权。入口在健康同构实例之间均匀随机分发新请求，目标实例满载即拒绝，不建立新任务等待队列，也不由 Worker 主动领取任务。

随机分摊的是请求数，不保证实时负载相等。不同任务耗时和工具占用不同，某台实例满载时，其他实例可能仍有空位。本方案不中心扫描 CPU 或选择最闲实例，也不自动轮询其他节点寻找空位。

## 触发与交接

| 项目 | 约定 |
| --- | --- |
| 触发 | 新任务到达选定实例，或原已受理 Run 需要恢复执行 |
| 输入 | 可信命令或 Run ID、Session 资格、实例容量、租户额度、状态与期限 |
| 输出 | 槽位预占、Session 资格、Attempt、owner、epoch 与 lease，或明确的准入结果 |
| 下一环节 | [03 Runtime 与环境准备](../03-runtime-setup/README.md) |

一个 Run 表示一次逻辑调用，一个 Attempt 表示一次 Worker 执行尝试。一次模型重试、工具重试或 Skill 加载不自动产生新 Attempt；重新分配 Worker 接续执行时才建立新的执行尝试。

细化专题见 [Worker 心跳租约与故障接管](./01-Worker心跳租约与故障接管.md)，分别说明实例存活、Attempt 执行权和任务进展。

## 新任务怎样准入

1. [任务接入](../01-request-entry/README.md)先完成可信身份、资源访问和幂等检查。已存在的相同请求返回原 Run，不因为当前实例满载而拒绝这次查询或重复扣占。
2. 目标实例以非阻塞原子操作预占执行槽位，生成预占标识。容量不足时复查并发提交的相同幂等记录，已有结果则返回原回执，否则立即拒绝新受理，不等待空位。已知提交结果不明时先对账。容量是可承载的执行上限，不能仅看 CPU 瞬时利用率。
3. 与任务接入在同一可靠提交边界裁决 Session 资格和租户额度，保存幂等、配置快照、Run、Attempt、owner、epoch、lease、`STARTING` 及原 ack。不同实例不能各用内存锁判定同一 Session 可用。
4. 确认事务失败时释放本次槽位，幂等竞争失败也释放多余预占。提交结果未知则先查询对账，避免已经受理却被误报为拒绝。提交成功后直接启动 Runtime，不再等待任务投递或领取。
5. 完成、取消或合法暂停后，按实际资源释放情况幂等回收槽位与额度。任务终态提交与 Session 资格释放使用一致的状态版本条件。

01 和 02 是可同进程实现的逻辑分工，不构成“先受理后等资源”的两段流程。默认同 Session 已有主 Run 时，新独立任务被拒绝。等待输入仍保留原 Run 的 Session 资格，即使释放 Worker 也不开放其他任务改写上下文。

补充输入、审批、取消等控制命令直接进入原 Run 控制接口，不参与新任务满载拒绝逻辑。恢复需要计算资源时仍要重新准入。并行子 Run 使用独立上下文，实际执行也需容量，预算计入父任务。

## 已受理任务的恢复

租约过期扫描和启动期限检查用于发现需要修复的 Run。恢复组件先核对可恢复状态，再按相同实例准入原则获取槽位和必要额度，原子取得新 epoch、创建接管准备中的 Attempt，并将 Run 转为 `STARTING`。隔离旧执行者并核对未决操作后接续。Run 快照、Session 资格、已用预算和总截止时间保持原任务语义。

无资源时按当前状态版本条件保存 `RECOVERY_PENDING`，或等价的恢复等待原因及 `next_retry_at`，不能覆盖已被其他实例接管的状态。按退避、次数和截止时间有限重试，超过约束则明确失败或等待人工处理。这是已受理任务的可靠性修复，不回到新任务队列，也不能再答复未受理。等待用户回复后的重新分配同样遵守容量限制。

## 边界与失败处理

连接所在节点不决定执行所在节点。实例选择与准入确定本次执行归属，Runtime 决定任务内部下一步。不同 Harness 通过适配器接入相同的 Run 和 Attempt 契约，详见 [参考实现与设计边界](../参考实现与设计边界.md)。

Worker 不再心跳并不证明它已经停止。新 Attempt 取得控制权后，开始新的业务动作前应终止或隔离旧实例，并让实际写入端拒绝旧令牌；已经发出的外部请求另行核对。Worker 租约失效不自动把 Session 资格交给另一独立任务，应先接管或结束原 Run。长时间人工等待能否释放 Worker，取决于 Runtime 是否具备持久化等待能力，合法释放不按心跳故障接管，见 [等待与恢复](../06-wait-recovery/README.md)。

槽位、额度预占与释放使用稳定标识并核对受理结果，实例故障后由恢复与清理记录完成回收。状态通知可使用 outbox，通知重试不能再次启动 Runtime。`STARTING` 期间也检查取消与权限状态。
