# MCP 与企业工具模块

本模块管理企业工具的接入、发现、版本和调用治理。MCP 服务与已有业务 API 通过统一目录和适配器接入，运行接口使用可信执行上下文，承担实际参数校验、授权及操作结果记录。

## 工具目录与调用治理

工具目录保存服务地址、接入方式、工具 schema、版本、负责人、凭证引用、可用范围和调用策略。已有业务 API 可以通过适配器进入同一目录，MCP 则提供标准化的工具发现与调用接口。

MCP 工具支持输入 schema 和可选输出 schema。工具行为注解有助于客户端理解能力，规范要求对非可信来源的注解保持不信任。因此，本基座将写入风险和授权规则放入受管理的策略记录。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

工具调用按以下顺序进行。

1. 发布 AgentVersion 时固定允许的工具集合和 schema 版本。
2. 运行时根据身份和任务范围筛选可见工具，将必要定义交给模型。
3. 收到调用后验证实际参数、资源归属、当前权限、审批要求及业务前置条件。
4. 写操作先保存稳定操作 ID、参数摘要与操作意图，再发起调用。
5. 校验结果并保存调用状态，大结果转为产物引用，返回可供下一步使用的摘要。

工具超时区分明确失败与结果不确定。创建工单、推送代码等操作优先使用对方幂等键。缺少幂等接口时，结合业务唯一约束及结果查询处理，无法确认的操作进入待核对状态。恢复 Run 之前先解决这些未决操作。

工具版本发生 schema 变化时生成新版本并做兼容验证。已发布 Agent 依赖的接口不可用时明确失败或停用，避免静默映射到新行为。工具接入方要支持版本约定，平台留存 schema 快照和调用版本以便排查。

HTTP MCP 服务按其授权协议验证访问令牌及目标受众，访问下游系统使用相应下游授权。stdio 服务由受控 Worker 启动，通过进程身份、环境和凭证范围建立边界。[MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

工具网关提供鉴权、限流、超时、审计和错误归一化。SDK 内置 Shell、文件及网络能力还需要沙箱约束，相关凭证和网络出口由环境策略控制。

在 Agent Runtime＋Skill＋工具的方案中，Skill 描述操作方法，业务服务检查强制条件。例如发布工具核验目标代码或产物版本对应的测试与审批记录，不能仅接受模型提供的“已通过”结论。条件不满足时返回具体原因，由 Agent 继续处理或请求人工输入；实际发布权限收敛到受控服务，避免通过其他工具绕过检查。

## 渐进式加载边界

平台先完成工具注册、连通性检查、授权和版本固定。模型侧按任务和当前身份获得相关工具的名称、用途及必要 schema，需要新增能力时再选择并提供对应定义。工具目录中可发现的工具不必全部进入每轮模型上下文。

MCP 提供发现与调用协议，按需筛选和注入 schema 由客户端或 Runtime 实现。SDK 是否允许运行中新增或移除工具需要在能力表中声明。只支持启动时配置的后端，应在启动边界确定工具集合，不能假设支持任意动态工具切换。统一的选择、注入与预算规则见 [上下文模块](../04-context/README.md)。
