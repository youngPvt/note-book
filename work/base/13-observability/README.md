# 可观测性模块

本模块关联运行状态、调用过程、资源用量与业务效果，支持排障、审计及统计。核心运行记录由持久化存储保证，遥测可以按策略采样，质量判定及版本对比由评测模块组织。

## 信号、关联与留存

以 OpenTelemetry 的 trace、metric 和 log 信号为接入基础，复用既有收集器与监控存储。具体 Agent 事件字段由平台维护版本，固定采用的语义约定版本。[OpenTelemetry 信号说明](https://opentelemetry.io/docs/concepts/signals/)

建议建立 `Run → Attempt → Agent 执行步骤 → 模型、Skill 加载、工具、记忆、沙箱操作` 的关联关系。步骤记录实际动作与结果，不要求预先定义业务流程节点；Runtime 能暴露内部节点时可附加记录。事件和 span 携带执行标识、组件版本、耗时和状态，敏感字段按规则脱敏。长时间人工等待记录独立事件和恢复关联，避免依赖一个长期打开的 span。

| 观测目标 | 建议指标或记录 |
| --- | --- |
| 执行准入 | 准入耗时、容量与会话冲突拒绝率、各实例请求数及执行并发 |
| 执行稳定性 | 已受理 Run 完成率、恢复等待时长、恢复成功率、取消耗时、失败类别 |
| 模型与工具 | 调用时延、限流与重试、实际或估算用量、待核对写操作 |
| 上下文与记忆 | 可见的材料 ID 和版本、召回时延、上下文裁剪、记忆更正与撤销 |
| 环境与产物 | 环境启动时延、资源峰值、归档失败、清理失败 |
| 业务效果 | 验收通过率、人工修改量、代表性问题正确率、每次有效交付成本 |

模型与 SDK 只暴露部分事件时，平台记录可见边界，缺失的内部调用或 token 细节标记为未知。排障依据输入输出、结构化动作、工具结果和验证证据。完整提示词或原始内容按授权与采样策略保存，访问日志同样有租户隔离。

新任务直接进入目标实例的准入过程，满载快速拒绝，因此不统计平台新任务排队时延。准入耗时覆盖身份与幂等检查、槽位和资格预占、可靠提交到返回 ack 的过程；拒绝按容量、Session 冲突、租户额度与权限等原因分组，并与已受理 Run 的执行失败分开。相同请求返回原 ack 的次数单列，不能当成新 Run 或重复扣量。

均匀随机分发在长期只使同构实例收到的请求数近似平均，任务时长不同会造成并发和资源占用差异；观测同时记录请求数、执行并发和拒绝率，不能据请求数宣称实时负载均衡。已受理任务的 `RECOVERY_PENDING` 单独统计等待时长、剩余截止时间和最终结果。模型提供商内部排队等真实下游等待可按可见证据记录，不能与平台准入混为一项。

运行状态和必要事件保存在业务持久化存储中，审计按保留规则保存，trace 可以采样。观测链路短暂故障不能导致运行状态丢失。必要审计或产物无法持久化时，对应受控动作暂停或失败并给出原因。
