# 上下文管理与渐进式加载

本模块属于执行层，独立目录用于继续细化上下文策略与资源装载，不是额外的初始化层或必须单独部署的服务。Context Assembler 统一选择首轮、后续轮次和恢复后每次调用需要的材料，ResourceLoader 负责鉴权、读取和返回版本化内容。以下为设计草案，SDK 的实际能力需通过适配器验证。

## 资源可用与模型可见

资源注册保存名称、类型、位置、版本和访问规则，索引支持发现，挂载让执行环境能够读取文件。模型输入由本轮实际提交的指令、消息、工具定义和读取结果组成。已注册或已挂载资源仍需经过选择与读取，才能作为内容进入模型输入。

MCP 提供工具发现与调用协议，模型请求中的工具选择和装载由客户端或 Runtime 实现。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

本方案中，原生工具定义通过模型接口的 `tools` 等对应字段提交，包含名称、参数 schema 和必要说明。Skill 正文、知识片段和文件摘要作为内容输入。发现工具返回的说明可帮助选择，后续调用还需模型接口暴露对应工具，或通过已暴露且受控的调用入口执行。

## 统一组装与运行状态

[执行准备](../03-preparation/README.md) 建立或恢复 Runtime，交付可信身份、Run 与 Attempt、固定配置、模型参数、预算和必要状态。它可以读取、校验指令模板，但不单独组装初始化 Prompt。后端运行信息用于控制与鉴权，不能整包放进模型输入。

[执行循环的上下文组装](../04-execution/01-context-assembly/README.md) 是统一入口：首轮从当前请求和必要历史开始，后续结合计划及工具结果，恢复后使用已核对的状态。三种情况共用选择、排列、授权过滤、预算和压缩策略，生成本轮模型输入。任务规划在紧接着的正常模型调用中完成。

固定配置与内容可按版本复用，变化状态随执行更新；每轮组装不要求重新读库、重新下载所有资源或发送全部历史。需要的内容被压缩后可以按引用重新读取，缓存命中仍需当前访问资格。内容过滤与工具执行前的实时授权分别落实。

## 各类资源怎样逐步加载

| 资源 | 初始可见内容 | 按需展开 |
| --- | --- | --- |
| MCP 工具 | 客户端获取目录，按任务与授权选择 schema | 加载候选工具定义，模型选择后校验参数并执行 |
| Skill | 名称、用途和适用条件 | 选中后读取固定版本正文，再按引用读取附属脚本、模板或资料 |
| 知识 | 查询命中的授权片段及来源 | 按文档版本扩展相邻段落、章节或表格 |
| 产物 | 清单、摘要、类型、大小和稳定引用 | 按文件、页码、行范围或其他受支持范围读取 |
| 长期记忆 | 与任务相关的条目摘要与验证状态 | 按 ID 和版本读取必要内容及支持证据 |

Skill 的元数据、正文及附属资源按需要装载，执行脚本仍需单独验证权限和环境条件。[Agent Skills 规范](https://agentskills.io/specification)

大量 Skill 的目录可以通过搜索按需暴露：模型先调用 `search_skills` 获得候选描述，再调用 `load_skill` 将选中版本的正文作为工具结果加入上下文。包文件是否已经下载、正文是否仍在当前上下文中，需要分别记录。具体链路见 [多租户 Skill 配置存储与运行时加载](../09-skills/01-多租户Skill配置存储与运行时加载.md#runtime的按需加载)。

Skill 的 `resources` 清单区分参考资料、脚本和模板等文件，`dependencies` 声明其他 Skill 或工具。内容缓存减少文件读取，上下文加载记录决定是否需要再次注入；预取文件不等于预先把正文放入模型输入。具体见 [Skill 数据模型与资源依赖](../09-skills/02-Skill数据模型与资源依赖.md) 和 [渐进式加载与缓存](../09-skills/03-渐进式加载与缓存.md)。

## 加载循环与预算

1. 每次模型调用前进入同一个 Assembler，首轮从准备层交付的运行信息与当前任务开始；后续或恢复后使用最新的运行状态。
2. 按固定策略保留强制约束和必要的发现或读取入口，再根据当前需要选择材料；Loader 每次读取检查可信身份、当前授权和版本。
3. 调用前检查预算，淘汰低相关历史、合并重复片段或生成带来源摘要，保留强制约束、未决事项和结果验证条件。
4. 把预算内的必要内容及工具定义提交给模型，按决策执行受控动作，将结果更新到运行状态；需要继续时回到同一个组装入口。

确定会用到的少量工具、任务约束和必要资料可以预加载，减少发现与读取的额外轮次。加载策略结合任务效果、上下文用量和端到端时延评测。

预算需覆盖指令、消息、工具 schema、读取结果，并给后续工具返回与模型输出预留空间。必要材料超出预算时缩小任务或分阶段执行，无法满足条件时返回明确原因。读取失败、版本失效和无权限分别记录，防止把缺失材料当作已确认事实。

## SDK 接入边界

平台自控调用可逐轮调整内容与工具集合。SDK 动态添加工具、读取挂载资源和修改内部历史的能力由适配器声明。只支持固定工具集合时，在启动前选定授权候选集，预加载必要定义并保留可用的发现入口。仅能返回目录的入口还需有受支持的调用路径。

SDK 创建会话若要求初始指令，适配器复用统一组装策略生成所需输入，不在准备层复制另一套规则。SDK 内部逐轮请求不可控制时，只在公开扩展点接入，不能把平台的设计目标当作所有 SDK 已支持的能力。

SDK 历史包含撤权内容且无法可靠清除时，停止受影响执行，用授权输入重建会话。内部 token、裁剪或工具选择过程未暴露时标为未知，观测记录实际提交的材料与可见事件。[观测模块](../13-observability/README.md)

## 后续细化专题

- 资源引用格式、范围读取与版本失效契约。
- 不同 Runtime 的发现、动态工具和预加载能力表。
- 预算分配、摘要保真与上下文清单的恢复规则。
- 联合评测模块验证发现成功率、必要信息遗漏、权限撤销和加载成本。[评测模块](../14-evaluation/README.md)
