# 沙箱与工作区模块

本模块准备和回收受限执行环境，管理任务工作区、资源限制、网络出口和临时凭证。它与执行层的 Attempt 所有权配合，保证恢复材料与实际文件状态一致。

## 环境与工作区生命周期

执行环境按模板创建，模板固定运行镜像、依赖、工具版本、资源限制、网络规则、文件挂载和凭证获取方式。Runtime 工作进程与任务环境可以分开管理，编码、命令和 Skill 脚本进入任务对应的环境。

沙箱按实际动作需要创建，普通问答和纯远端 API 调用不必分配任务沙箱。[Runtime 基础初始化](../03-execution/03-runtime-setup/README.md)默认只保留环境策略和申请接口；只有任务入口已明确要求、Runtime 启动硬性依赖或接续状态需要时，才提前准备最小必要环境。运行中申请环境先校验当前授权、配额和 Attempt 所有权，使用稳定创建标识处理超时与重复请求。

| 阶段 | 处理要求 |
| --- | --- |
| 准备 | 验证模板与授权，准备仓库基线或输入文件，创建独立工作区 |
| 分配 | 绑定 Run、Attempt 与执行所有权，限制 CPU、内存、磁盘、进程及存活时间 |
| 运行 | 注入限定范围的短期凭证，控制网络出口和可写目录，上报存活状态 |
| 暂停或故障 | 保存恢复所需会话数据、工作区版本与文件清单，核查外部副作用 |
| 回收 | 归档必要产物和诊断信息，确认持久化，再释放环境并撤销凭证 |

容器可以承载普通隔离工作负载，更强的隔离要求需要沙箱容器或虚拟机等机制。容器共享宿主机内核，选择环境时需匹配所运行代码的信任程度。[Kubernetes 多租户与沙箱说明](https://kubernetes.io/docs/concepts/security/multi-tenancy/#sandboxing-containers)

恢复需要同时考虑 Runtime 会话与文件系统。例如模型记得某个文件已修改，而新工作区仍在旧基线上，继续执行就会使用错误前提。因此恢复清单同时关联 checkpoint、仓库基线、文件快照或补丁、依赖环境和未决操作。

租约失效后，旧进程的文件写入仍可能发生。优先使用 Attempt 独立目录，新 Attempt 从已提交版本恢复，通过带所有权校验的产物提交更新当前结果。必须复用同一持久卷时，先确认旧进程已停止并独占挂载。

生产系统访问、Git 推送等能力使用限定身份和受控服务，避免将宽权限凭证放入任意脚本可读取的环境。只读数据和输入文件也按当前任务授权准备。
