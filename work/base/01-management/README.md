# Agent 基座管理层设计

管理层（Management）负责租户、身份、Agent 配置、能力目录、权限策略和配额的管理，向执行层提供可校验的发布版本及可信执行上下文。它是平台配置与治理的入口，可以先作为 Spring Boot 后端中的一组模块实现。

其职责包含配置保存、校验、发布、回滚、停用和审计。执行层负责模型调用、任务循环与恢复，各资源服务在访问时落实管理层规定的限制。

本方案采用 Agent Runtime＋Skill＋工具。管理层管理能力与运行配置，AgentVersion 不绑定 Workflow 模板；任务步骤由 Skill 描述，模型在 Runtime 中根据目标和反馈决定执行动作。整体边界见 [Agent Runtime 与 Skill 的执行方案](../00-overview/README.md#agent-runtime-与-skill-的执行方案)。

本文为设计方案，字段和接口是建议契约。面试描述中的实施范围、个人贡献和上线日期需对应实际项目记录。

## 租户、工作区与身份

Tenant 是隔离和配额的顶层边界，Workspace 承载租户内团队或项目的资源。单企业内部使用时，可以先配置一个租户、多个工作区，数据模型保留多租户能力。

| 对象 | 管理内容 | 关键约束 |
| --- | --- | --- |
| Tenant | 状态、管理员、配额、保留策略 | 禁用后拒绝新任务，撤销访问，并处理进行中的 Run |
| Workspace | 成员、项目资源、共享范围 | 资源共享需要明确授权 |
| Subject | 用户、服务账号及其代理关系 | 登录身份来自企业身份系统，后台调用保留实际委托者 |
| RoleBinding | 角色、成员、作用域 | 区分管理 Agent、发布、调用和查看执行记录 |
| CredentialRef | 凭证引用、归属、用途、有效期 | 密钥正文放凭证系统，按执行需要获取短期授权 |

服务端根据验证过的身份建立 `tenant_id`、`workspace_id` 和 `subject`。API 中的资源 ID 与身份所属范围交叉校验，前端或模型提供的租户字段不能直接决定访问权限。

租户隔离贯彻到关系库查询、检索过滤、缓存键、对象存储访问、工作目录和事件订阅。内部服务间同样验证身份及资源归属。平台管理员、租户管理员与普通使用者的权限分开定义。

## 租户配置与运行时读取

租户配置服务属于管理层，提供统一管理和读取入口，维护租户状态、可用资源范围、权限策略和配额。Agent 从租户可用范围中选择自己的能力，发布后固定具体依赖版本。

运行链路先通过认证确定可信租户身份，再读取对应租户及 Agent 配置。服务端把身份与版本信息放入执行上下文，传递给 Runtime、队列任务和资源服务。各模块共用配置来源，并在实际访问时执行限制。

配置读取支持缓存和变更失效；固定 AgentVersion 保证依赖一致，当前租户状态与授权仍能限制后续动作。完整职责、读取契约及链路见 [租户配置服务与执行权限](./02-租户配置服务与执行权限.md)。

## Agent 配置与发布

Agent 保存名称、负责人和用途，AgentVersion 保存某个可执行版本。配置草稿可编辑，发布版本不可变。对外调用只需 `agent_id` 和任务输入，由服务端解析当前发布版本，创建 Run 时保存实际采用的运行配置快照。已创建的 Run 在执行、重试和恢复时沿用原快照，客户端无需重复携带版本号。

| 配置组 | 建议内容 |
| --- | --- |
| 输入输出 | 输入 schema、输出 schema、结果验证规则 |
| 指令与方法 | PromptVersion、允许加载的 SkillVersion、入口已指定 Skill 的加载配置 |
| 执行方式 | Runtime 类型、适配器版本、所需能力、执行环境模板、循环与工具调用限制 |
| 模型策略 | ModelProfile 版本、参数范围、允许的备用模型、费用与时限 |
| 工具与知识 | 已批准的工具版本集合、知识集合、资源范围 |
| 记忆与上下文 | 记忆类型及作用域、写入规则、召回策略、上下文预算 |
| 治理策略 | 权限策略引用、审批规则、并发上限、保留策略 |

发布流程采用 `DRAFT → VALIDATED → PUBLISHED → DEPRECATED`。校验包括引用存在、Runtime 能力匹配、工具参数兼容、环境可用，以及配置要求的回归样本通过。弃用版本停止承接新调用，其历史记录继续可查。需要停止旧版本运行时另发停用指令。

已指定的入口 Skill 也必须属于该 AgentVersion 允许的集合并通过当前授权校验。配置发布后，执行层直接创建 Run、组装上下文并启动 Agent 循环，不以流程模板或节点连线作为运行前提。

发布时固定依赖版本与内容摘要，事务性更新发布指针和审计记录。并发编辑通过 `revision` 条件更新避免覆盖，切换默认版本通过条件更新避免两个发布互相覆盖。回滚将默认指针指向先前通过验证的版本，记录回滚原因。

版本固定支持问题复现，实时授权决定当前还允许访问什么。即使 Run 引用旧配置，已经撤销的仓库权限、工具授权或凭证也必须生效。

普通配置升级影响新 Run；权限撤销、危险能力禁用和版本停用约束正在运行的任务。配置内容、运行进度与当前授权分别保存，旧版本保留用于追溯不代表仍可执行。完整的快照内容、请求链路、缓存边界及权限误开放示例见 [Agent 配置发布与运行快照](./03-Agent配置发布与运行快照.md)。

## Skill 授权与 Agent 绑定

Skill 可用范围分为全局和非全局。非全局包括租户自己上传的 Skill，以及平台授权给该租户的定制 Skill。Skill 的归属与可用范围分别记录：平台拥有的 Skill 也可能只对指定租户开放。

管理层维护 `tenant_skill_grant` 和 `agent_skill_binding`，分别表达租户获授权的 Skill，以及 AgentVersion 启用的具体 SkillVersion。全局 Skill 不逐租户生成授权记录，租户上传的 Skill 按归属识别。当前 Agent 的候选范围为“全局、租户自有、平台授权的并集”，再与 Agent 配置启用的集合取交集。

控制台通过 Skill 模块的管理接口展示目录、上传内容和选择版本。Skill 服务统一维护目录、版本与包地址，管理层保存配置引用，不再复制 Skill 正文。二者可以先作为同一个后端中的不同模块，共用关系库。

具体数据结构、发布流程以及运行时的搜索与加载，见 [多租户 Skill 配置存储与运行时加载](../08-skills/01-多租户Skill配置存储与运行时加载.md)。

## 权限与审批

权限可先采用 RBAC 管理角色，再以资源属性和作用域约束具体访问。一次操作的有效权限由用户或服务身份授权、Agent 能力上限、任务授权范围和当前策略共同收窄。

| 检查点 | 判定内容 |
| --- | --- |
| 发布 Agent | 发布者是否能引用目标工具、模型、知识与 Skill |
| 创建 Run | 调用者是否能使用该 AgentVersion，输入资源是否在授权范围内 |
| 读取上下文 | 文档、记忆、历史会话和产物是否对当前主体可见 |
| 执行工具 | 当前动作、目标资源和实际参数是否允许，是否需要审批 |
| 查询或恢复 | 调用者是否仍可查看结果、提交输入、恢复或取消 Run |

管理层维护策略及审批规则，连接层检查会话访问、订阅与用户命令，执行层和公共组件在实际访问时继续检查。工具描述中的“只读”、Prompt 中的约束以及 Skill 声明都只能辅助选择，权限由服务端策略计算。

审批记录绑定 `run_id`、动作、目标资源、参数摘要、工具版本、有效期和审批者。参数变化或授权过期时重新判定。恢复执行先核验审批记录与当前权限，再把审批关联到稳定的操作 ID。重试复用同一操作结果，避免重复消费审批后再发起相同写入。

审批等待状态由执行层保存，审批资格和结论由管理层管理。需要当前 SDK 无法提供的审批能力时，发布校验应阻止该配置进入执行。

审批之外的业务条件由对应工具或业务服务核验。例如发布服务检查目标代码或产物版本的测试记录及审批条件，避免引用其他版本的结果。管理层保存策略与资源引用，Skill 提供操作指导，实际受控动作依赖服务端检查结果。

## 大模型配置与调用治理

管理层维护 Provider、ModelProfile、凭证引用、能力标签和用量策略，并将发布的模型配置交给执行路径。模型目录与授权在管理层管理，实际调用、降级和用量采集由模型运行组件落实。详见 [模型接入与调用治理](../06-models/README.md)。

## 配额、审计与管理接口

租户和工作区可以配置并发 Run、排队长度、模型用量、沙箱资源及产物存储额度。创建 Run 时预占必要额度，执行期间追加检查，结束后按实际用量结算。用量事件以稳定 ID 去重，重试 Attempt 的成本计入同一 Run。

管理审计记录操作者、对象、变更前后版本、时间和原因。配置发布、权限修改、凭证轮换、审批、停用及数据删除都保留可查询记录，敏感凭证不进入审计正文。

下表包含管理接口及管理界面调用的运行接口，资源路径中的租户与工作区始终由服务端鉴权。连接与会话职责见[连接接入模块](../02-connection/README.md)，Run 创建及快照固定由执行层负责。

| 接口职责 | 请求重点 | 返回或效果 |
| --- | --- | --- |
| 创建或修改 Agent 草稿 | 配置、`expected_revision` | 草稿版本或并发冲突 |
| 验证与发布 AgentVersion | 依赖版本、评测记录 | 不可变版本与发布记录 |
| 调整模型与能力目录 | 模型、工具、Skill、环境引用 | 可用范围与能力校验结果 |
| 更新策略或成员绑定 | 作用域、权限、预期版本 | 新策略版本与失效通知 |
| 提交执行请求 | `agent_id`、输入、幂等键 | 经连接模块转交执行层，幂等创建 Run、固定快照并入队 |
| 提交审批结论 | 审批对象、预期状态、结论 | 决策记录及恢复通知 |
| 查询审计和用量 | 已授权的对象范围、游标 | 分页记录与统计口径 |

管理事务与通知使用 outbox 连接，避免数据库已经更新而下游未收到事件。授权关键路径查询当前有效状态，缓存按策略版本失效。停用与撤权事件用于及时停止受影响任务，执行前检查作为兜底。

## 面试表达

> 用户只选择 Agent，管理层在后台维护发布版本，执行层创建 Run 时保存运行配置快照。执行层按快照使用模型、工具、Skill 和环境，重试与恢复保持一致；权限撤销和停用按当前有效状态检查。这样既能解释一次任务用了什么配置，也能及时阻止已经不允许的动作。

复习时可以用“发布一个只能查指定知识库和工单的助手”演示完整链路，再补充权限撤销、版本回滚和模型降级三个追问。
