# 一周面试复习与深度自测

复习目标是把已有工程经验组织成清楚、具体、经得住追问的项目表达。一周内开始面试，先快速覆盖全部模块，再集中处理陌生点和深度不足的部分。模型微调不列入本次范围。

## 先判断哪里需要深入

每个模块先脱稿讲两分钟，再回答下表中的追问，根据表现标记掌握程度。

| 标记 | 判断方式 | 下一步 |
| --- | --- | --- |
| 熟悉 | 能讲清职责、具体实现、失败路径及方案取舍 | 简要记录关键词，进入下一个模块 |
| 待深入 | 概念清楚，但到状态、接口、并发或故障处理时卡住 | 带着卡点读对应章节，补一张图或一条执行时序后再答 |
| 待补齐 | 概念混淆，无法解释适用场景或控制过程 | 先读专题中的定义与例子，再回到工程问题 |

掌握程度与项目参与情况分别记录。对每项能力注明实际负责设计、参与实现、接入已有能力或仅做过验证，说明自己控制的边界。新补的验证可以帮助理解，项目经历仍使用实际交付的任务。

## 面试回答要达到的深度

一个模块按下面的顺序展开。短回答先覆盖前两项，遇到追问再进入实现、取舍和故障细节。

1. **业务与约束**：解决哪类问题，输入、输出和完成条件是什么。
2. **职责与边界**：本模块负责什么，与上下游怎样交接。
3. **实施细节**：接口、核心数据、状态变化、存储和执行时序。
4. **方案取舍**：比较过哪些选择，为什么适合当时的团队、业务和规模。
5. **故障处理**：哪一步可能失败，怎样检测、恢复和核对外部结果。
6. **贡献与验证**：自己做了哪些决定和实现，用什么记录确认效果。

架构深度可以通过一条真实请求展开。比如解释 Run 和 Attempt 后，继续说清任务领取、状态写入、工具副作用、工作区恢复与结果提交如何配合。引用框架能力时，区分框架已经提供的机制和自己补充的逻辑。

## 十三个模块的快速自测

| 模块 | 应能具体讲出的实现 | 用来检查深度的追问 |
| --- | --- | --- |
| [01 管理层](../base/01-management/README.md) | 租户身份、AgentVersion、授权与审批记录 | Run 固定旧配置，用户权限随后被撤销，下一步操作依据什么判断？ |
| [02 连接接入](../base/02-connection/README.md) | 请求、会话、连接路由、状态同步与发布排空 | 网关发布后换节点重连，怎样找回原 Run，避免重复创建与遗漏状态？ |
| [03 执行层](../base/03-execution/README.md) | Run、Attempt、checkpoint、Worker 所有权与停止条件 | 工具已完成写入但响应丢失，新旧 Worker 又同时存在，怎样接续？ |
| [04 上下文](../base/04-context/README.md) | 本轮输入清单、渐进式加载、预算与摘要 | 压缩时怎样保留未决动作、关键约束和证据？摘要丢了细节怎么办？ |
| [05 记忆](../base/05-memory/README.md) | 四类记忆的读写、来源、作用域和修订 | 错误经历被写成长期事实，怎样发现、更正并处理后续引用？ |
| [06 模型](../base/06-models/README.md) | 调用适配、能力契约、Prompt 与输出校验 | 备用模型不支持相同 schema 或工具行为时，降级还能直接继续吗？ |
| [07 MCP 与工具](../base/07-mcp/README.md) | 注册发现、参数校验、授权、操作记录与结果核对 | 第三方创建接口没有幂等键，调用超时后依据什么决定是否重试？ |
| [08 Skills](../base/08-skills/README.md) | 元数据、正文、脚本、发布版本与按需加载 | Skill 发布了新版，运行中的任务怎样保持方法与脚本版本一致？ |
| [09 知识检索](../base/09-knowledge/README.md) | 解析切分、召回、权限过滤、重排与引用 | 检索到了正确文档却回答错误，如何定位问题发生在哪个环节？ |
| [10 沙箱](../base/10-sandbox/README.md) | 工作区、资源限额、凭证、网络和恢复清单 | 模型会话记得文件已改，但新工作区还是旧版本，能否直接恢复？ |
| [11 产物](../base/11-artifacts/README.md) | 内容存储、元数据、版本、授权和归档时序 | 文件上传成功但元数据未提交，或状态先成功而文件未保存，如何处理？ |
| [12 可观测性](../base/12-observability/README.md) | Run 关联的事件、日志、Trace、用量与权限 | 用户只反馈“任务很慢”，怎样区分排队、模型、工具、重试和人工等待？ |
| [13 评测](../base/13-evaluation/README.md) | 样本版本、验证证据、指标分母与回归 | 模型变快了，但人工修改增加，怎样判断整体收益？ |

每道追问先按自己的实际实现回答，再讨论其他方案。暂时卡住的地方写成具体问题，例如“响应丢失后靠哪个字段查回 MR”，便于下一轮定点补齐。

## 七个专题的深入标准

专题入口集中在 [知识清单](../base/README.md)。复习时检查能否回答下面这些问题。

- **本体与执行循环**：能画出模型决策、工具执行、观察反馈和停止分支，说明哪些步骤由代码控制。
- **规划与反思**：能用同一个任务解释 ReAct、Plan-and-Execute、Reflection 的选择与组合，并区分反思、重试和重新规划。
- **Prompt 与结构化输出**：能设计正常、缺信息、拒绝和截断分支，说明格式合法之后为什么仍要校验业务语义和权限。
- **推理与模型选型**：能解释上下文、首字延迟和任务时延，拿业务样本比较模型能力、成功率、修正成本及降级兼容性。
- **多 Agent**：能判断何时采用单 Agent，何时拆分子任务，并讲清上下文、权限、预算、文件冲突和结果汇聚。
- **自动化评测**：能定义完成条件与指标分母，固定样本和版本，隔离重复试验，并说明模型评分如何由人工校准。
- **执行安全**：能分别处理幻觉、提示注入、越权和重复副作用，指出检查发生在模型输入、服务端还是执行环境。

## 一周安排

前两天先保证能够完整介绍项目并回答执行主链路。后续安排根据自测标记调整：熟悉的主题快速过，腾出的时间用于实际卡点。

| 时间 | 复习重点 | 当天应留下的结果 |
| --- | --- | --- |
| 第 1 天 | 脱稿讲项目主线，快速自测十三模块与七专题 | 一张架构图，一条端到端任务链路，一份具体卡点清单 |
| 第 2 天 | 连接与任务解耦、执行循环、状态恢复、MCP 调用与副作用 | 讲通正常流程、网关重启、响应丢失和 Worker 崩溃的不同处理 |
| 第 3 天 | 上下文、记忆、RAG、Prompt 与模型调用 | 讲清一次请求的材料来源、预算分配、输出校验及失败归因 |
| 第 4 天 | 权限、Skill、沙箱、产物 | 讲通从授权到执行、审批恢复、结果持久化的边界 |
| 第 5 天 | 多 Agent、Trace 与 Eval | 比较单多 Agent 方案，用明确口径解释如何定位和验证效果 |
| 第 6 天 | 结合简历进行一轮完整模拟追问 | 检查每段经历的职责、关键决策、具体实现和验证记录是否连贯 |
| 第 7 天 | 重答卡住的问题，精简项目表达 | 稳定的两分钟概述、五分钟架构讲解及几组能展开的实际案例 |

如果面试提前，优先完成全量自测、项目主线、执行恢复和与目标 JD 对应的短板。已能稳定回答的内容无需反复通读。

## 项目口述与案例

实际案例、整体架构口述和个人贡献记录统一放在 [项目口述与案例整理](./02-项目口述与案例整理.md)。

## 六个架构深度追问

1. 编码任务修改文件后崩溃，怎样判断可以恢复原 Run？何时需要关联的新 Run？
2. 创建 MR 已成功但响应丢失，旧 Worker 尚未停止，新 Worker 怎么接手？
3. 等待审批期间用户被撤权，旧内容还在缓存和模型上下文里，怎样处理？
4. 增加创建人筛选为什么需要多个 Agent？单 Agent 或并行 Worker 能否满足？
5. 更换模型或增加 Reflection 后，怎样确认质量和整体成本确实改善？
6. 选一个实际需求，从入口讲到验收，指出你亲自负责的决定和实现，以及框架提供的部分。

回答后检查是否包含具体对象、执行次序、失败分支和验证方法。只说“做了幂等”“用了记忆”“加了评测”时，继续追到操作 ID、记忆条目或样本评分规则这一层。

## 每轮复习怎样进行

先脱稿回答，再做追问，最后回看文档。可以将一次练习组织为简短口述、实现追问、一个故障场景和卡点记录，避免一边阅读一边误以为已经能够独立表达。

每个卡点只记录四项：原问题、没有讲清的环节、补充后的关键逻辑、下一次验证方式。理解不牢的部分先画流程；涉及行为差异且资料不足时，再用小范围实验核对。
