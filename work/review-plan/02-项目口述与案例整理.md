# 项目口述与案例整理

结合自己的实际职责准备项目表达，技术概念与实现细节统一查阅 [知识清单](../base/README.md)。下面按整体架构、具体任务和个人贡献组织材料。

## 基座架构口述

> 基座我按四部分设计。管理层负责租户、Agent 发布版本、权限和模型配置，执行层驱动 Agent 循环，按需加载 Skill、调用工具，管理上下文和中断恢复。底层通过适配器接入 LangGraph 自定义 Runtime 或成熟 SDK，统一任务入口与结果，同时保留后端能力差异。
>
> 记忆采用工作、情景、语义和程序性四类。工作记忆跟随运行状态，长期记忆通过独立生命周期管理。公共组件提供 MCP 工具、Skill、知识检索、沙箱、产物和观测评测。
>
> 这些模块通过统一的租户身份、版本引用和 Run 标识连接。部署上先合并通用管理模块，执行资源按需独立扩容。企业助手和需求流水线共享基座，分别维护自己的业务入口和验收条件。

## 一条需求的讲述顺序

1. 说明目标、输入仓库、验收条件和授权范围。
2. 说明 Skill 方法指导、Agent 动态决策与程序强制检查的边界，以及何时规划、查询、改代码及重新规划。
3. 说明每轮上下文、工具定义、记忆与知识证据从哪里来。
4. 说明输出如何校验，写入如何授权，任务怎样等待、恢复或结束。
5. 判断是否需要多 Agent；需要时明确每个子任务的输入、产物与汇聚规则。
6. 展示测试、审查和运行记录，按预先约定的口径比较质量、时延及成本。

## 准备三类实际案例

**企业助手案例**：选择一个真实的知识问答或业务查询任务，串起身份、检索、上下文、工具和回答验证。重点解释权限与证据怎样影响最终结果。

**研发流水线案例**：选择一个实际交付的微型需求，从需求输入讲到代码修改、测试、审查和结果留存。选一个真正遇到的难点，说明自己怎样定位和处理。

**平台架构案例**：选择 CarryGo 中一条自己参与的跨服务链路，说明服务职责、数据归属、任务交接、状态回传和关键取舍。按当前实际工作范围展开。

每类案例用同样的字段记录：业务任务与约束、自己负责的范围、核心接口或状态、关键选择及替代方案、实际问题和处理、验证方式、仍有的局限。

可用的依据包括自己的设计记录、代码变更、接口契约、脱敏时序、日志归因和验收记录。对有统计口径的数据说明样本、时间窗口及分母；没有统一指标时，用具体案例及可核查结果讲清变化。

## 个人贡献与验证记录

每个重点专题准备一份能展开的记录：实际任务与约束、自己负责的部分、关键状态或接口、遇到的故障、处理办法和验证结果。架构设计、参与实现和独立交付分别表述。

口述时先解释选择及边界，再给具体任务。能够回答“为什么这样做”“失败时怎样处理”“如何确认做对了”，比只列框架和模式名称更有帮助。
