## 案例一 中文诉求无法匹配目录

### 典型问题

用户输入“零策素材”，希望调用灵策相关能力。旧 `find_skill` 实测返回零命中，后续能力选择缺少正确候选。问题出现在用户称呼与目录可检索文本的匹配环节。

### 原因

旧逻辑只匹配 Skill 名称及截短的英文描述。中文称呼、别名与现有元数据之间缺少有效关联，仅依靠这部分文本匹配无法召回目标 Skill。

### 解决方案

本次修复将已授权 Skill 目录放入模型提示词，并补充中文显示名与别名，给模型提供识别用户意图所需的候选信息。后续装载与调用的访问检查，属于复用此方案时需要验证的权限边界。

## 案例二 跨行 YAML 描述被截断

### 典型问题

Skill 元数据中的描述采用带引号的跨行 YAML 写法。Tool Market 解析后只取得首行，导致市场展示及索引使用的描述不完整，能力发现依赖的信息随之缺失。

### 原因

解析流程没有把描述的续行作为完整字段处理，截断发生在元数据生成阶段。因此，即使召回逻辑正常，后续组件也只能使用已丢失信息的描述。

### 解决方案

提供的修复摘要为先合并续行，再处理引号与转义，并增加对应回归用例。排查同类问题时，可沿原始描述、解析结果、市场元数据和索引字段检查内容是否一致，定位信息最先丢失的位置。

## 待改进 目录超预算时相关能力可能被裁掉

### 典型问题

目录超过提示词预算后，仍按名称排序裁剪。与当前问题相关的 Skill 可能位于截断部分，模型因此无法展开该能力。目录规模增长会再次影响发现效果。

### 原因
