# 非当前必需参考文件缺失阻断任务准备

本案例依据用户提供的故障与修复摘要整理，归类为 Skill 资源依赖与加载时机问题。缺失资源是否阻断执行，需要结合它在当前步骤中的实际用途判断。

## 典型问题

`wechat-hotspot-publish` 缺少一个当前步骤用不到的图片参考文件，托管任务却在准备阶段被拦截。任务尚未运行到需要该文件的步骤，准备过程就因这个缺失项整体失败。

这使“资源清单中存在缺失”和“当前任务无法继续”被当成了同一种状态，非当前必需的参考资料成为启动条件。

## 原因

本例在启动检查中把参考文件缺失直接作为准备失败条件，即使当前步骤并不使用该文件。资源存在性检查因此提前阻断任务，影响范围大于当时实际依赖该资源的步骤。

## 原修复

准备阶段记录缺失项，并保留当前绑定的 Skill 版本。实际读取缺失资源时，返回具体文件错误；只有当前步骤确实依赖该资源、无法继续时，才暂停处理。

这一规则适用于本例中的非当前必需参考文件。缺少核心正文或当前必需资源，仍然是实质缺失，不能概括为所有缺文件都可忽略。也不通过自动切换最新版补齐文件，以免执行过程中改变既定资源版本和行为。

## 验证状态与证据

用户提供的历史记录显示，使用原包的离线复测已完成任务准备。这个结果只证明该准备场景解除阻断，不代表整个任务执行、发布或后续图片处理全部成功。

摘要对应的本轮验证中，提供者因本机 `x-coder` 版本不匹配，未复跑托管资源测试套件。因此，历史离线准备结果与本轮未复跑状态应分别保留。

## 可补充验证

以下是建议检查项，尚未执行：

1. 非当前必需文件缺失时，确认准备完成且缺失项被保留记录。
2. 执行到依赖该文件的步骤时，确认错误指出具体文件，并暂停受影响流程。
3. 核心正文或当前必需资源缺失时，确认不能被当作可忽略项放行。
4. 准备、读取和恢复过程均核对绑定版本，确认未自动切换到最新版。
