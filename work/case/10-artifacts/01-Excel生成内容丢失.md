# 产物生成与内容完整性

本知识点关注 Skill 已经执行、文件也已经生成，但产物没有完整保留输入内容的问题。以下案例依据提供的 Nexus 排查摘要整理，来源和验证说明见 [案例总览](../README.md#本批案例的来源与验证范围)。

## 案例一 生成 Excel 时丢失表格外的内容

### 典型问题

`generate_document` 生成 XLSX 时，只保留了输入中的表格。标题、说明段落和列表没有进入生成结果，导致文件存在、表格可读，但文档信息不完整。

这类问题发生在 Skill 自身的产物生成逻辑。继续优化 Skill 召回，或者反复加载相同正文，不能直接修复已经确定的内容转换缺失。

### 原因

原记录描述的生成流程只保留表格数据，没有为表格之外的标题层级、段落、列表及内容顺序提供对应的输出形式。

Excel 的数据工作表适合后续计算，但单靠数据工作表不足以表达原文的全部结构。文件能够打开或生成工具返回成功，也不能证明输入信息已完整转换。

### 解决方案

修复落在生成脚本中，保留原有数据工作表，同时增加“文档内容”工作表：

1. 原数据工作表继续保存表格数据，保留原有使用方式。
2. “文档内容”工作表按输入顺序保留标题层级、段落、列表和表格位置。
3. 数据读取与完整内容回顾分别有对应工作表，减少转换时遗漏非表格信息的问题。

这里的修复目标是内容和结构信息保留，不据此推断 Excel 与原文具有完全相同的视觉排版。

### 可补充的验证

以下为后续验证建议，不代表原记录已经执行：使用同时包含多级标题、说明段落、有序和无序列表、多张表格的输入，检查生成文件中的顺序与内容对应关系。

| 检查对象 | 需要确认的结果 |
| --- | --- |
| 原数据工作表 | 原有表格数据仍保留，便于继续计算与分析 |
| 文档内容工作表 | 标题层级、段落及列表内容没有丢失 |
| 混合内容顺序 | 文本与表格之间的位置关系仍可辨认 |
| 无表格输入 | 不因缺少表格而生成空内容文件 |
| 只有表格的输入 | 不破坏已有数据导出行为 |
