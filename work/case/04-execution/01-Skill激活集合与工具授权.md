# Runtime 中 Skill 激活集合与权限守卫不一致

本案例依据提供者的原排查记录整理，涉及工具激活与文件读取范围两个问题。源码定位来自原记录，当前电脑无法访问对应仓库。

## 典型问题

任务先加载知识检索 Skill，再加载待办管理 Skill。知识检索工具仍出现在模型可见列表中，权限守卫却只认可最近加载的 Skill，导致模型调用被拒绝并反复尝试重载。

另一个问题是上一轮的文件读取限制影响了新任务，将本应允许的读取误拦截。

## 原因

工具清单与守卫采用的状态范围不一致。模型依据可见工具选择动作，守卫却只检查最近一个 Skill，无法正确处理多个 Skill 仍处于有效激活状态的情况。

文件读取限制的生效范围也超出了当前请求。原记录没有提供具体上下文变量及实现细节，本文仅保留已描述的边界问题。

## 原修复

- **激活集合校验**。守卫改为检查当前仍有效的已激活 Skill 集合，支持调用其中允许使用的工具。
- **请求范围限制**。文件读取限制限定于本次请求，避免上一轮限制继续误拦截后续任务。

## 设计边界

已激活集合应表达当前运行中仍有效的能力，不能直接累积所有历史加载记录。其范围仍受当前租户与 Agent 配置限制，停用或失效的 Skill 不能因曾经激活而继续获得调用资格。

有效工具的可见范围与守卫判定应保持一致。激活状态、文件缓存和正文是否仍在模型上下文中是不同状态，缓存命中或历史加载都不能单独作为授权依据。

让模型通过 Prompt 反复重载只能绕过部分表象，修复需要落在运行状态与守卫判定的一致性上。
