# Skill 正文被工具结果截断

本案例依据用户提供的故障与修复摘要整理，归类为 Skill 指令传输与模型上下文问题。核心现象是 Skill 显示加载成功，但模型下一轮没有收到完整操作步骤。

## 典型问题

某个 Skill 的 `SKILL.md` 较长。加载动作完成后，正文经过 SDK 的通用工具结果处理，被截断为部分内容。后续模型请求缺少关键步骤，执行行为因此偏离 Skill 的完整要求。

这里需要区分三个检查点：资源已读取、工具已返回、正文已进入下一次模型请求。前两个环节成功，不能证明第三个环节的内容完整。

## 原因

Skill 正文承载执行指令，却进入了通用工具结果的截断路径。该路径限制返回内容长度时，没有保留这些指令完整传输的语义，加载成功状态也未反映下一轮上下文的实际缺失。

问题发生在内容传输边界。只检查工具调用状态或重新加载同一资源，都不足以确认模型看到了被截掉的部分。

## 原修复

为授权通过的 Skill 正文与包内 Markdown 增加有预算的传输处理：预算内恢复原文，超过单份文档上限时明确提示分页读取，避免把残缺内容当作完整指令继续使用。

这一处理针对指定文档类型，不代表一般工具结果可以无限免截断。授权、单份上限和上下文预算仍然有效，超过上限需要通过显式读取继续获得内容。
